## 1. 合并原则

不要把所有 CSV 直接横向合并成一张表。原因是多数表是一对多关系:

- 一个达人有多条趋势日期记录。
- 一个达人有多个带货品类/品牌。
- 一个达人有近 10 场直播、近 10 条视频。
- 一个达人有大量直播/视频词段。

如果硬 join，会产生笛卡尔积，行数暴涨且指标重复。建议采用“达人主宽表 + 多张明细事实表 + 聚合特征表”的结构。

## 2. 推荐输出

### 2.1 达人主宽表: `mart_blogger_profile.csv`

粒度: `blogger_id` 一行一个达人。

来源:

- `bloggers.csv`
- `detail_summary.csv`
- `api_status.csv` 聚合结果
- `commerce.csv` 聚合结果
- `fans_trend.csv` 聚合结果
- `overview_lives.csv` 聚合结果
- `overview_videos.csv` 聚合结果

建议字段:

- 基础信息: `blogger_id`, `Nick`, `KwaiId`, `CateName`, `Fans`, `Score`, `BloggerJumpUrl`
- 搜索指标: `VideoCount`, `LiveCount`, `ShopLiveCount`, `AvgPlay`, `SalesPrice`, `AvgCustomerPrice`
- 视频汇总: `视频_视频数_当前`, `视频_播放数_当前`, `视频_点赞数_当前`, `视频_评论数_当前`, `视频_分享数_当前`
- 直播汇总: `直播_直播数_当前`, `直播_带货直播_当前`, `直播_推广商品_当前`, `直播_预估直播销量_当前`, `直播_预估直播销售额_当前`
- 覆盖状态: `has_commerce`, `has_fans_trend`, `has_overview_lives`, `has_overview_videos`, `has_segments`
- 带货聚合: `top_category`, `top_category_amount`, `top_brand`, `top_brand_amount`, `commerce_total_amount`
- 趋势聚合: `latest_fans`, `fans_start`, `fans_end`, `fans_growth`, `views_growth`, `likes_growth`, `comments_growth`
- 近 10 直播聚合: `recent_live_count`, `recent_live_sales_amount`, `recent_live_volume`, `recent_live_max_watch`
- 近 10 视频聚合: `recent_video_count`, `recent_video_views`, `recent_video_likes`, `recent_video_comments`
- 来源: `_search_sources` 或拆成 `source_sorts`

### 2.2 趋势事实表: `fact_blogger_trend.csv`

粒度: `blogger_id + Date + series`。

直接来自 `fans_trend.csv`，保留长表结构:

- `series=total_fans`
- `series=increment_fans`
- `series=total_video`
- `series=increment_video`

用途:

- 画粉丝增长曲线。
- 计算日增粉、播放、点赞、评论。
- 观察爆发日期。

### 2.3 带货事实表: `fact_commerce.csv`

粒度: `blogger_id + type + Name`。

直接来自 `commerce.csv`:

- `type=category`: 品类分布
- `type=brand`: 品牌分布

用途:

- 达人主带货品类。
- 品牌集中度。
- 品类/品牌销售额 TopN。

### 2.4 内容事实表

保留两张:

- `fact_recent_lives.csv`: 来自 `overview_lives.csv`
- `fact_recent_videos.csv`: 来自 `overview_videos.csv`

用途:

- 近期直播销售表现。
- 近期视频播放、点赞、评论表现。
- 识别内容效率。

### 2.5 词段事实表: `fact_segments.csv`

来自 `segments.csv`。

用途:

- 评论/弹幕高频词。
- 达人内容标签或受众关注点。
- 后续可以做词频、聚类、主题分析。

## 3. 清洗计划

### 3.1 字段类型清洗

统一把展示型数值转成数值:

| 示例 | 数值 |
| --- | ---: |
| `1.9w` | 19000 |
| `1.50亿` | 150000000 |
| `9999.0w` | 99990000 |
| `-` | 空值 |
| 空字符串 | 空值 |

建议保留两列:

- 原始展示值: 如 `Fans`
- 数值列: 如 `Fans_num`

### 3.2 ID 和去重

主键使用:

- `blogger_id`: 脚本内部统一字段
- `BloggerId`: 搜索接口原字段

清洗时统一成 `blogger_id` 字符串，所有表按该字段关联。

去重规则:

- `bloggers.csv`: `blogger_id` 保留一行。
- `detail_summary.csv`: `blogger_id` 保留一行。
- 明细表保留自然粒度，不强行去重；只去掉完全重复行。

### 3.3 覆盖率检查

用 `api_status.csv` 生成覆盖标签:

- `has_commerce = LiveShopData_Cate_count + LiveShopData_Brand_count > 0`
- `has_fans_trend = LstFansData_count + LstIncFansData_count + LstVideoData_count + LstIncVideoData_count > 0`
- `has_overview_lives = Top10LiveDatas_count + Top10LiveDatas2_count > 0`
- `has_overview_videos = Top10VideoDatas_count > 0`
- `has_segments = LiveSegments_count + VideoSegments_count > 0`

这一步可以区分“API 返回为空”和“解析遗漏”。

### 3.4 趋势清洗

`fans_trend.csv` 是长表，建议拆/聚合:

- 按 `series` 过滤。
- `Date` 转日期。
- 数值字段 `Fans`, `TotalComments`, `Likes`, `TotalViews` 转数值。
- 计算每个达人:
  - 起始粉丝 `fans_start`
  - 结束粉丝 `fans_end`
  - 粉丝增长 `fans_growth`
  - 最大日增粉 `max_daily_fans_growth`
  - 播放增量 `views_growth`
  - 点赞增量 `likes_growth`
  - 评论增量 `comments_growth`

### 3.5 带货清洗

`commerce.csv` 中 `Ratio` 是金额。

按达人聚合:

- `commerce_total_amount = sum(Ratio)`
- `top_category = type=category 中 Ratio 最大的 Name`
- `top_category_amount`
- `top_brand = type=brand 中 Ratio 最大的 Name`
- `top_brand_amount`
- `category_count`
- `brand_count`

### 3.6 近 10 场直播/视频清洗

直播聚合:

- `recent_live_count`
- `recent_live_sales_amount = sum(TotalPrice)`
- `recent_live_volume = sum(TotalVolume)`
- `recent_live_max_watch = max(DisplayWatchCount)`
- `recent_live_avg_watch`

视频聚合:

- `recent_video_count`
- `recent_video_views = sum(ViewCount)`
- `recent_video_likes = sum(LikeCount)`
- `recent_video_comments = sum(CommentCount)`
- `recent_video_avg_view`
- `recent_video_interaction_rate = (likes + comments) / views`

## 4. 分析方案

### 4.1 达人分层

按粉丝和商业表现分层:

- 头部达人: 粉丝高、销售额高、近期直播强。
- 高潜达人: 粉丝中等，但互动率或增粉强。
- 内容型达人: 视频播放强，直播/带货弱。
- 带货型达人: 销售额强，视频互动一般。
- 低活跃达人: 视频/直播/趋势为空或长期低值。

### 4.2 带货分析

维度:

- 品类 TopN
- 品牌 TopN
- 达人带货金额 TopN
- 达人主品类集中度

目标:

- 找到高 GMV 达人。
- 找到某品类下可合作达人。
- 判断品牌投放集中度。

### 4.3 内容效率分析

指标:

- 视频播放 / 粉丝数
- 点赞率
- 评论率
- 近 10 条视频平均播放
- 近 10 场直播人气峰值

目标:

- 找出粉丝不高但内容效率高的达人。
- 识别直播强但短视频弱的达人。

### 4.4 增长趋势分析

指标:

- 期间粉丝增长
- 最大日增粉
- 播放/点赞/评论增长
- 增长波动性

目标:

- 找近期增长快的达人。
- 识别异常增长或热点爆发。

### 4.5 数据质量分析

用 `api_status.csv` 输出:

- 每个 API 的覆盖率。
- 每个 sort 的有效达人占比。
- 空数据原因分布。

这一步很重要，因为不同 `sort` 返回的人群质量差异很大。`sort=0` 大量低活跃小号，`sort=5/9/10` 更偏高带货达人。

## 5. 推荐落地步骤

1. 先保留当前原始 CSV，不覆盖。
2. 新增一个合并脚本，例如 `scripts/ks_feigua_merge_csv.py`。
3. 脚本读取最新 `data/ks_feigua_csv_*` 目录。
4. 输出到新目录 `data/ks_feigua_mart_<timestamp>/`。
5. 生成:
   - `mart_blogger_profile.csv`
   - `fact_blogger_trend.csv`
   - `fact_commerce.csv`
   - `fact_recent_lives.csv`
   - `fact_recent_videos.csv`
   - `fact_segments.csv`
   - `quality_report.csv`
6. 后续分析优先使用 `mart_blogger_profile.csv`，需要明细时再关联事实表。
